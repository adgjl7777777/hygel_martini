## 프로그램에서 달라진 점

### 1. 계획 기반 연결을 명시적으로 요구할 수 있다

`require_explicit_crosslink_plan: true`를 설정하면 계획 정보가 모두 없어졌을 때 오류로 중단한다. 계획된 연결을 잃고 기존 기하학적 연결 방식으로 넘어가는 경우를 막는다. 기존 입력에서 이 설정을 생략하면 이전 동작을 유지한다.

### 2. 실제 저장된 결합을 다음 준비 단계 전에 검사한다

계획한 연결을 `planned_crosslinks.json`으로 남기고, 백본과 화학 구조의 ITP 파일을 쓴 직후 각각 다시 읽어 검사한다. 계획된 연결의 누락·중복·잘못된 연결을 발견하면 중단한다.

결합 하나를 지워도 전체 그래프가 여전히 연결된 시험 사례에서, 새 검사는 누락을 검출했다. 실제 실행 순서를 사용하는 오류 주입 시험으로 다음 준비 단계가 호출되지 않는 것도 확인했다. 검사는 등록된 연결점과 사슬 끝의 결합을 대상으로 하며, 모든 화학 상호작용이나 계산 완료 뒤의 수동 파일 변경까지 감시하는 기능은 아니다.

### 3. 재현 예제에서 발견한 설정 오류를 수정했다

기존에는 `add_water.enabled: false`여도 물 설정 블록이 있으면 물 추가 단계가 실행됐다. 이제 물·이온·분자·고분자 추가를 명시적으로 끈 설정을 존중한다. `enabled`가 없는 입력의 기존 의미는 유지하며, 문자열 `"false"`처럼 잘못된 불리언 입력은 오류로 알린다.

### 4. CI가 배포 파일을 시험하도록 바꿨다

소스 폴더에서 editable 설치를 시험하던 방식을 바꿨다. wheel을 만든 뒤 새 가상환경에 설치하고, 소스 폴더 밖으로 시험을 복사해 실행한다. GitHub Actions에는 Python 3.11/3.12 구성을 작성했다. 이번에 실제 실행해 확인한 것은 로컬의 깨끗한 Python 3.12.12 환경이며, 원격 Actions 실행을 완료했다고 주장하지 않는다.

작은 예제는 물을 넣지 않은 짧은 PEGDA 구성 시험이다. 초기 구조 완화와 MD를 생략하고 실제 구성·파일 검사·GROMACS 전처리를 실행한다. 따라서 물성이나 평형 상태를 새로 검증한 결과로 세지 않는다.

전체 시험은 먼저 만든 wheel에서 실행했다. 최종 배포본은 문서와 예제 설명을 보완해 다시 만들었으며, 시험한 wheel과 **모든 패키지 코드·내장 리소스가 바이트 단위로 같음**을 확인했다. 각각의 wheel 체크섬은 검증 JSON에 기록했다.

## 논문은 어떻게 보강했는가

새 Figure 4는 같은 끝점 좌표에서 다음 세 가지를 나란히 보여준다.

1. 요청한 연결: a–b, c–d.
2. 거리 기반 방식이 선택한 연결: a–c, b–d.
3. 계획 기반 방식이 유지한 연결: a–b, c–d.

이를 통해 **연결 설계를 실제 분자 결합까지 보존한다는 기여**를 바로 볼 수 있다. 그림은 실제 함수 호출 결과에서 생성했고, 원래 논문에 기록된 0.1.0에서도 같은 결과를 확인했다. 다른 프로그램과의 성능 순위나 새로운 물성 계산으로 표현하지 않았다.

개정 검토본의 과학적 근거와 소프트웨어 스냅샷은 기존 Series-01과 같다. 새 안전장치와 63개 시험은 별도의 **0.1.1.dev0 개발 버전** 성과로 기록했다. 기존 원고·제출 패키지·물성 수치·원본 소프트웨어 체크아웃을 보존했으며, 개정본의 변경 diff와 출처·체크섬을 함께 남겼다.
